# P0 baseline: payload, subject identification and live lessons (2026-11-09)

This is the measured starting point for the subject plugin plan (octos-learn `docs/SUBJECT_EXPANSION_PLAN.md`, P0). Plugin work in P1 and P2 is compared against these numbers.

## Setup

| Item | Value |
| --- | --- |

| Jev | `jev-latest` through Octos Learn's signed-in BYOK relay (the key stays server-side). It answered as `jev-1.14.0` on image requests. |

Raw results are in `eval/baseline-2026-11-09/`. `lessons-traces-images.tar.gz` holds the final lessons, generation traces and rendered test images.

## 1. Payload, offline

`npm run payload:measure` generates the 8 course fixtures through every input route and request path with no model call. Largest request (system prompt + prompt + response schema):

| Route | First request | Fallback outline | Later section | Repair | Practice |
| --- | ---: | ---: | ---: | ---: | ---: |
| Self-contained | 15,852 B | 7,669 B | 8,261 B | 8,355 B | 1,772 B |
| Text / voice | 17,099 B | 8,947 B | 8,261 B | 8,355 B | 1,772 B |
| Camera | 18,197 B | 9,066 B | 8,380 B | 8,474 B | 1,891 B |
| Selection | 18,681 B | 9,066 B | 8,380 B | 8,474 B | 1,891 B |

The response schema is about 7 KB of a 17 KB first request. `eval/payload-ceilings.json` records these maxima as hard ceilings (decision S6), and `test/payload-ceilings.test.mjs` enforces them.

**Provider token counts leave out the schema.** On the first request, `prompt_tokens` divided by the system-prompt and prompt bytes has a median of 0.25 tokens per byte. Dividing by the full request including the schema gives 0.14. The schema is evidently not counted. Byte ceilings therefore remain the payload gate. For a token figure that includes the schema, use the provider's token-counting API on the full request.

**No prompt cache hits.** `cached_content_tokens` was 0 on all 120 first requests. Ordering prompts for implicit caching brings no benefit today, so it should not drive the design.

## 2. Subject identification with Jev

Two versions of the subject question were each sent for all 93 requests:
- **(A)** today's admission gate, verbatim, with choices math, physics, general_science, language_humanities and other;
- **(B)** the proposed plugin question, with choices math, physics, chemistry, biology and unclear.

| | A (today) | B (plugins) |
| --- | --- | --- |
| Typed requests, correct top subject | 83 / 84 (put "转圈怎么变成正弦波？" under physics) | **84 / 84** |
| Camera and selection requests, text only | Image not seen; answers "other" | Image not seen; answers "unclear" (correctly falls back to the broad request) |
| Latency | p50 238 ms, p95 437 ms, max 595 ms (both versions) | |

**With the image attached.** Jev 1.13+ reads images from a top-level `assets` map, but only with the header `TypeSafe-Danger-Zone-Images: true`. Octos Learn's relay needs octos-org/octos-learn#132 to send it. With the image attached, version B got the right subject for all **9 / 9** readable images and returned clarify for the blurred page, in 0.25–0.64 s. TypeSafe labels image input experimental, so keep the text-only fallback.

**Simulated routing, version B, text requests.** A first subject at or above T1 is selected; a second subject at or above T2 is added; otherwise the broad request is used. Mixed requests give the second subject little weight (0.08–0.37), which drives the choice of T2.

| T1 / T2 | Scoped, correct | Broad | Wrong subject (one reroute) | Unneeded plugin |
| --- | ---: | ---: | ---: | ---: |
| 0.6 / 0.05 | 70 | 7 | 1 (MX-en-02) | 0 |
| 0.6 / 0.10 | 69 | 7 | 2 | 0 |
| 0.6 / 0.20 | 67 | 7 | 4 | 0 |
| 0.8 / 0.20 | 64 | 10 | 4 | 0 |

The remaining 15 requests are ones Jev did not treat as lesson requests. T1 0.6 / T2 0.05 is the proposed starting point. These thresholds were tuned on the same requests, so they need confirming on held-out requests before scoping is switched on.

**A problem in today's gate.** For two follow-ups whose meaning is clear from the board's previous lesson, Jev chose clarify: "那晚上植物还会这样吗？" ("Do plants still do that at night?") and the heating-curve follow-up. Today's gate would ask the learner to clarify instead of teaching. When the same requests reached Coach directly, it generated lessons for both.

## 4. Lesson quality, sampled review

12 lessons were reviewed against the rubric: goal match, whether the visual shows the relationship, agreement between narration and visual, subject accuracy, and request coverage. Lessons reviewed: PH-en-01, PH-en-04, CH-en-02, BI-en-01, MA-en-01, IM-03, IM-08, FU-03, FU-06, MX-zh-01, CH-zh-01, AM-en-05.

- **Goals and coverage:** good in all 12. Camera and selection lessons read the image correctly (IM-03 solved the pictured system; IM-08 explained the pictured equation). Follow-ups referred to the board (FU-03), or correctly ignored it for an unrelated request (FU-06, the French Revolution).
- **Visuals for science are weak.**
  - Chemistry and biology lessons use only notes, formula cards and step diagrams.
  - Math cards are used as text boxes (a slogan, the history lesson's motto).
  - The water cycle is drawn as a straight list instead of a cycle (Phase B item B3).
  - Physics lessons fit when a shared graph suffices (PH-en-01 speed graph, MX-zh-01 Hooke's law) or when the existing spring recipe applies (PH-en-04).
- **Accuracy and narration problems:**
  - MA-en-01 writes `2·(−1) < 4·(−1) ⟹ −2 < −4` on the board without saying it is the wrong version.
  - AM-en-05 states an invented figure ("500 billion liters").
  - IM-08 merges reactant and product oxygen counts into one chain.
  - PH-en-01's narration says the speed is 2 m/s after the slider was animated to 4, and asks the learner to set it "back to 3" mid-lesson.
- **Level:** BI-en-01 answers "How do plants make their own food?" with the Calvin cycle and NADPH. The level is not fitted to the question.

## 5. What this means for the plan

1. **Jev can serve as the subject signal for every input route,** once #132 lets images through. Start with T1 0.6 / T2 0.05, and confirm on held-out requests.
2. **Payload gates stay in bytes.** Use the provider's token-counting API when token figures that include the schema are needed. Don't plan around prompt caching until it is shown to work.
3. **Separate from plugins, but found here:**
   - optional practice questions should be dropped, not allowed to fail a lesson that is already playing;
   - the answer check needs a tolerance for rounded values;
   - the gate's false clarify on clear follow-ups needs fixing.

   These show up as failures and latency in every comparison, so fixing them first keeps the plugin comparison clean.
4. **Science needs real visuals.** The value of the physics, chemistry and biology plugins (vectors, particle models, labelled pictures, true cycles) is visible in this sample.

## Reproduce

```bash
npm run payload:measure                                              # offline payload
node scripts/live/render-images.mjs OUT/images <octos-learn>/node_modules/playwright/index.mjs
node scripts/live/jev-baseline.mjs OUT/jev.json 186                   # text, through Learn's relay
LEARN_ORIGIN=<relay with #132> node scripts/live/jev-images.mjs OUT/jev-images.json OUT/images
node scripts/live/lesson-baseline.mjs OUT 120 OUT/images              # live lessons through local Octos
python3 scripts/live/analyze-jev.py OUT/jev.json
python3 scripts/live/analyze-lessons.py OUT/lesson-baseline.json
```

The live scripts sign in as the local owner and use that profile's own keys through Octos and Learn. Every run spends the owner's API credit.
